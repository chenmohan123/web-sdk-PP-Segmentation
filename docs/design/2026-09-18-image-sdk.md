# PP-Segmentation 图片版设计

状态：用户已确认依据2026-09-18可行性报告继续推进独立图片SDK；本文落实接口、默认值和本轮验收。首版为本地0.1.0-alpha.0，不包含远程发布。

## 任务与取舍

独立`web-sdk-PP-Segmentation`承载实例分割任务，首个模型为`ppyoloe-seg-s-640-fp32`。输入单帧Blob或RGBA，输出类别、分数、原图像素框与逐实例mask。保持各实例重叠，序号不表示跨帧跟踪。

采用在CPU恢复紧凑ROI二值mask的方案：实现成本和可验证性适合首版，Worker隔离交互。全图mask为参考路径，仅用于独立对照；GPU自定义mask shader需要额外兼容与数值证据，留到确有性能需求时评估。两次双线性插值和640网格裁剪顺序必须与官方一致，不能以直接裁剪160网格替代。

## 公共接口

`createSegmentation(options)`返回`manifest`、`capabilities`、`loadTimings`、`load({signal,onProgress})`、`run({image},{signal,scoreThreshold,nmsThreshold,maxDetections})`、`dispose()`。

- 模型清单字段：id/version/url/bytes/sha256。内置模型固定本次身份/字节数/摘要；公共接口允许调用者提供符合相同四输出契约的显式清单，验证身份非空、URL、正整数字节数和SHA256格式，并在下载后检查实际完整性。自定义清单不构成其他模型兼容承诺，无静默换源。
- backend为`wasm|webgpu`，默认wasm；executionMode为`main|worker`，默认worker；runtimeBaseUrl指向构建后的Worker/ORT静态文件目录。
- PixelImage为`{width,height,data:Uint8Array|Uint8ClampedArray}`，要求正整数尺寸、恰好width×height×4字节、最多16,777,216像素。SDK不分离调用者原有buffer；透明像素合成白底。
- 单帧结果：`{image:{width,height},instances,runtime,model,timings}`。instance为`{classId,label,score,box:{x,y,width,height},mask:{x,y,width,height,data:Uint8Array}}`。mask行优先，0/1，原图整数偏移，ROI外为0；空mask用0宽高/空数据表示。框裁剪在原图边界内。紧致ROI包含二次插值后的全部前景，可能超出检测框，绘制应使用mask.x/y而非box坐标，不得再次按框裁剪。
- scoreThreshold默认0.5，范围[0,1]，保留严格大于阈值的分数；nmsThreshold默认0.7，范围[0,1]；maxDetections默认100，范围1～300。逐类NMS保留top1000，最终按score递减；类别以COCO80连续classId表示。
- 总返回mask字节数上限64MiB，超出时报`OUT_OF_MEMORY`，不静默丢实例。逐实例中间缓存可复用，禁止同时构建300幅整图浮点mask。总输入限制不代替返回mask限制。
- 单实例同时只允许一个load/run，冲突报BUSY；未load、已dispose、非法输入、下载/校验/会话/推理错误使用稳定code。取消请求不输出过时结果；main内核不可强制中断，完成后丢弃结果；Worker释放可立即终止。abort后同实例可以恢复运行或重新load，dispose后不可复用。

预处理为RGB直缩640、bicubic(A=-0.75)并量化回uint8后除255，NCHW。Blob通过浏览器解码，显式EXIF和白底处理；记录decodeMs。数值评估同时保留与OpenCV差异和同输入官方参考，避免把解码/预处理差异误认成模型误差。

## 执行与资源

下载、版本化IndexedDB缓存和SHA-256由runtime管理；网络与缓存都验证摘要。Worker接收SDK拥有的模型/像素buffer；结果mask buffer转移回主线程。ORT版本1.27.0、WASM单线程、显式执行提供程序；GPU不可用时报UNSUPPORTED。记录requestedBackend/actualBackend、executionMode、runtimeVersion，不声称逐算子全GPU。

load记录modelDownloadMs/modelCacheReadMs/integrityMs/sessionMs；run记录decodeMs/preprocessMs/inferenceMs/postprocessMs/totalMs。totalMs为公共run请求到结果返回的墙钟耗时，包含Worker传输，不含load或UI绘制。

## Demo和分发

React参考Demo以Detection线上页面为视觉基准：深色顶栏、左侧参数与状态、中间图片、右侧结果与折叠信息，桌面采用三栏工作台。小于1200px时结果移到图片下方，小于700px时控件改为顶部网格。统一紧凑控件、蓝色分段按钮、边框、小圆角与共享UI tokens，图片结果优先。原图/mask叠加、实例选择、中文/英文、CPU/GPU与main/Worker、加载进度、取消和清理缓存保持可用。选中提示放固定工具栏，避免图片位置变化。390px无横向溢出；实例选择与中英切换保持图片位置。2026-09-18的[视觉修正及验证](../../reports/2026-09-18-ui-alignment/README.md)替代此前未充分对照Detection的卡片布局。

正式来源选项仅ModelScope/Hugging Face，默认ModelScope。尚无正式远程模型时明确显示本地开发状态，开发服务器提供固定哈希本地模型；两个正式来源不可假装可用。生产Demo不得依赖开发URL，也不得内置ONNX；缺少已发布来源时禁用运行并说明原因。门户本轮只更新规划。

## 本轮验收

1. 有意义单测先失败后实现：输入边界、输出/NMS语义、ROI与官方mask恢复、内存上限、下载完整性、竞争/取消/释放、缓存隔离。
2. SDK类型/构建、React Demo类型/构建、Vanilla基线示例、打包不含模型校验。
3. 固定64图含COCO segmentation GT，公共API CPU/GPU×main/Worker；另测Blob、空白、取消恢复、重复释放。AP评测score=0.01/maxDetections=100，与同输入Paddle官方基线比较，mask AP下降≤0.5个百分点作为转换验收值；score>0.5实例用同类别框IoU匹配，maskIoU≥0.99。未通过需报告差异原因，不改变门槛掩盖失败。
4. 比较实验参考后处理与优化实现的同输入掩码、耗时和返回字节数。性能数据限定当前硬件/浏览器，不由GPU网络推理耗时推导FPS。
5. 真实浏览器Demo桌面/390px、中英切换、结果选择不跳动、输入替换与取消验证；图片使用本地测试数据，生产示例素材另行核验许可。
6. SDK前后标准检查，双语README/六指南、CI与发布检查清单。模型来源未发布和远程治理未配置如实保留，不标stable。
