# FP32 首版发布准备

用户在 2026-09-18 确认继续质量收尾、来源许可核验和独立 SDK 发布准备。沿用当前 `codex/segmentation-image-sdk` 分支，保持 Detection 风格和桌面优先，不扩展精度、视频或门户组合。

## 原图尺寸契约

`run()` 解码后的整数 `image.width/height` 是输出坐标系的权威尺寸。掩码恢复到完整原图，ROI 不能因浮点缩放系数反算尺寸再截断而丢失最后一行或一列。检测框仍独立裁至原图边界，ROI 保留二次插值后的全部前景。

现有 SDK 已遵循此规则。固定上游 CPU 参考把 `im_shape/scale_factor` 转 `int`，会出现 612→611；旧报告按未经修正的上游行为比较，其失败结论必须保留。

新增一组明确标为“原图尺寸参考”的验证：从固定上游模型及掩码处理重新运行，只修正最后裁剪使用的整数尺寸；阈值仍为 AP 下降 ≤0.5 个百分点、全部 `score>0.5` 匹配实例 mask IoU ≥0.99、双方未匹配实例计失败。验证原始/修正参考在共同区域逐像素一致，保留补丁与来源摘要；不能从 SDK 掩码补齐参考。复用旧 SDK 四组合输出前必须验证模型、输入、代码和归档摘要。

## 执行范围

1. 在 `reports/2026-09-18-original-size/` 归档独立参考、64 图完整原图比较、尺寸回归及复算入口。旧 `reports/2026-09-18-image-sdk/` 保持原样。
2. 核验官方权重来源、许可声明和分割头第三方来源，形成带版本和 URL 的事实记录；只在证据支持时上传 ModelScope/Hugging Face。
3. 准备 Demo 双源解析与选择，默认 ModelScope。未发布来源保持空清单及禁用状态；生产产物不内置模型或开发覆盖。
4. 更新双语公开文档、验收与发布检查清单，执行标准检查、相关测试、构建、浏览器验收和独立审查。
5. 前述条件满足后，继续独立仓库、npm、GitHub Release 与 HTTPS Demo 发布；需要账号验证时只请求必要登录操作。许可或质量有实质未决项时记录具体证据与下一步，不把本地准备写成已发布。

## 任务分工与边界

| 任务 | 产物 | 与其他任务接口 |
|---|---|---|
| 原图尺寸参考 | 新数值脚本与报告 | 不改 SDK runtime；主流程引用真实结论 |
| 权重许可追溯 | 发布准备目录内许可报告 | 不上传权重；发布须依据其具体证据 |
| 双源接入 | Demo 来源解析、空来源清单及测试 | 不填虚构 Hub revision；不改 SDK 数值代码 |
| 主流程收尾 | 契约、公开文档、验证及审查 | 等各项证据后更新结论 |

旧 AGENTS 和清单中“本轮不发布”描述的是此前本地阶段。当前授权允许向上述发布流程推进；质量、许可和可验证来源仍是实际依赖，不能以授权代替这些事实。
